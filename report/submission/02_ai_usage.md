# AI 使用说明

使用工具：OpenAI Codex 对话式编程代理、终端与源码检索、Python脚本、Git、Torch profiler；用户在可访问GPU的容器终端执行实验命令。外部实现调研使用公开上游源码/文档。未将AI建议或生成日志当作真实实验结果。

AI协助：阅读题面与ATOM/Mellum源码、制定适配路线；编写模型配置与权重映射、审计与参考兼容路径；开发诊断、批量campaign、性能分析和接口启动脚本；提出并实现原生路径、graph、融合、cache与metadata实验；整理报告、证据与Git历史。

人工参与：确定Step0/Step1目标与时间预算；明确冻结环境与参考环境分离；在GPU容器执行命令并反馈；推动由逐token诊断扩展到HumanEval，随后再次核对题面token硬门槛；决定独立保守/激进交付模式。

错误与发现：早期set无法JSON序列化、AITER导入路径、MellumRotaryEmbedding API参数不匹配，均由实际报错定位修正。验证schema新增字段一度使比较器失败；显式schema/manifest修复。过度依赖短输出和局部精确曾低估长生成分叉，扩大200条与长输入后暴露。HumanEval较好曾使优化优先级偏向功能指标，但最终核对原题确认token门槛独立存在，因此不把功能分数作为通过替代。GPU基准与实际后端审计用于避免开关未执行、规模不一致或虚构收益。

验证边界：AI没有在当前受限工具环境启动GPU任务；GPU结果来源于用户执行留下的文件。CPU单元/静态检查不代替GPU smoke。最终激进配置仍未通过200条90%门槛，保守配置缺少此精确预设的独立HumanEval/完整ABC，报告明确披露。没有生成答案缓存、公开集硬编码或将不同配置结果拼接为合格成绩。

来源与保留：上游ATOM/AITER/HF/EvalScope/HumanEval按SOURCES.md注明；保留许可证与Git历史。AI生成代码经源码核对、CPU检查及实际实验逐步检验；受时间约束未完成题面完整三点累计消融，这一缺口没有用AI推测补齐。
