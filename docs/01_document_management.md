# 文档管理约定

## 分类与命名

- docs：题目来源、稳定背景、当前方案与重要决策。
- report/research：已有调查证据；report/validation：真实验证；report/performance：profiling与消融；report/submission：正式材料。
- report/archive：停止维护的历史原文，不作为当前执行入口。
- 同目录同类文档使用两位递增前缀，按编号阅读；README、MELLUM_ATOM_RESEARCH_GUIDE.md、worklog.md与原始附件例外。
- 序号是稳定的文档标识/默认阅读顺序，不是自然日。新文档取下一号，一般修订不改名、不重排。确需拆分或重排时同步更新导航与引用。
- Step0/Step1只用于题目阶段；不再以D0/D1或Phase表示长期文档类别。

## 更新职责

| 内容变化 | 更新位置 |
|---|---|
| 环境背景/长期约束变化 | Guide；附实际证据 |
| Step0范围或阶段状态变化 | plan/01_step0.md；结果主事实链接阶段总结 |
| 已验证基线配置、命令与回归安排 | plan/05_step0_baseline_and_reproduction.md |
| Step1候选、计点边界与测量计划 | plan/06_step1_optimization_routes.md；实际性能另记performance |
| 重要方案取舍变化 | plan/02_decisions.md，说明替代关系 |
| 新源码/容器发现 | 对应research主题，附日期、版本、符号和依据 |
| 实际执行检查/实验 | validation或performance；链接原始结果 |
| 当天完成/阻碍/下一步 | worklog.md当天条目 |

每个事实维护一个主要位置，其他页面链接引用；不逐轮追加新的全量阶段汇总。用户明确要求阶段收尾时可建立一个阶段总结主入口，引用既有实验而不复制全部流水；其配置与命令统一由基线说明维护。已确认、推断、待运行验证、未找到必须区分；未找到需说明搜索范围。源码行号绑定commit，更新后必要时复核。

## 测试和实验记录

脚本放工程合适位置，说明与结果分开。结果文档记录commit、依赖、模型/数据、命令、关键配置、参考来源、指标与结论边界；原始日志/输出放workspace的results/logs，不塞进导航或每日总结。文档序号稳定，同一次实验的多次运行通过运行ID及原始结果区分，不覆盖数据。

validation/performance/submission在有实际内容时再建目录，不生成伪结果占位文档。最终≤4页报告与1页AI说明从证据整理，不直接提交内部长报告。

## 每日日志

只有report/worklog.md按自然日期组织，每天一个条目，简记完成、发现/决策、验证状态、问题/下一步和详细链接。当天多轮追加/合并到同一条目。首次条目为已有记录整理，不补造时间或提交；正式提交若要求WORKLOG.md/D1–D7，可从唯一日志导出映射，不维护两套日记。

## 重构和归档

迁移前保留原文与SHA256清单，归档README标注替代文档。旧文本中的路径/方案视为历史快照，不批量改写其证据。新文档中的文件链接必须有效；原始PDF保持字节不变。
