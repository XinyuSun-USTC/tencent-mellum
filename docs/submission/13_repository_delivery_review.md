# 提交仓库核对

## 入口与配置

根目录仅保留start_server.sh作为统一入口，支持step0、step01、step012、step0123累计配置，以及重复使用--disable-opt 1/2/3。默认配置等于消融末行。全部配置使用单卡32槽；关闭参数及实际引擎命令记录于独立启动目录的launch.json。新增逐项开关通过CPU组合测试与预生成检查，未为非累计组合新增GPU性能或正确性成绩。

旧保守/激进入口和旧PDF生成器移至scripts/internal，旧PDF仅输出到历史归档目录。正式技术报告、AI说明和DAY0—DAY7日志均在根目录，README集中说明启动、开关、状态及证据。

## 验证结果

- 88项相关CPU测试通过，包括累计配置、逐项开关、旧入口兼容与SSE解析。
- 四个累计配置及逐项关闭场景的启动预生成检查通过：实际优化项、32槽、KV写入和prefix/chunk选项一致。
- 交付检查器核验文件、证据哈希、主要Markdown链接、分页结构、优化定义及可执行入口，无错误。
- Bash语法检查通过。当前改动主要涉及入口、开关、文档及工具整理，没有新增模型数学实现。

此前四行实际GPU入口smoke均通过。此轮新增开关的非累计组合仅完成CPU及预生成检查；README未赋予其已有累计行的成绩。完整正确性仍为前三行通过，step0123的token检查失败，C均存在超时，状态按实测披露。

## 仓库整洁性

已跟踪文件中无模型权重、虚拟环境、Python缓存、私钥及外部软链接。最大的单文件约11.8MB，为原始profiler trace。artifacts保存原始数据和失败证据，不以缩小仓库为由删除；目录用途在README说明。

运行输出写入被Git排除的results目录；预生成审查文件写入/tmp。Git保留完整提交及标签，打包工具从干净HEAD生成源码ZIP与完整历史bundle，交付包位于仓库外。
