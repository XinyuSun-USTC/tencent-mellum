## 2. 当前Git审计与收敛规则

审计时主工作目录分支为step1/profiling-baseline，HEAD为784820e；本地main及缓存origin/main仍指向Step0归档f382471，当前分支较缓存origin/main多64个提交。此次未联网刷新远端，因此这些是本地引用事实，不宣称远端实时状态。最新fastpaths代码在独立分支step1/basic-fastpaths的68a4086，并非当前主目录源码。

worktree共享Git对象，但文件版本独立。只推送main不会自动把其他分支未合入的实验代码交付出去。后续采用：

1. 等正在运行的批次结束，记录对应源码提交与实际配置；不修改运行目录。
2. 新建独立release/step1集成分支与worktree，将选定功能分支和文档分支正常merge，保留父提交；解决冲突后重新验证。
3. 给被采用/放弃的重要实验保留分支或带说明的标签。失败实验不必全部进入最终可执行代码，但相关历史、证据和放弃理由要保留。
4. 固定最终提交与提交标签；最终报告、配置、运行manifest记录同一版本。不要squash、force push或重写已有历史。
5. 提交前将最终分支/标签及必要实验引用推送个人仓库，核验远端可访问。GitHub推送是否等于正式交卷，仍以对接方提交渠道为准。

早期Step0以真实快照归档，已保留上游历史；不能把后补说明包装成当时已有的逐日源码提交。文档整理的实际提交时间也应如实保留。

## 3. 最终仓库与证据组织

建议最终布局（以下为待形成的真实交付内容，不提前创建空报告）：

- README.md：最终版本、声明卡数、启动命令、冻结环境、开关与复现索引。
- start_server.sh：项目相对路径启动，模型目录/端口可配置；使用给定运行环境，不运行安装或升级。
- configs/：Step0、+点1、+点1+2、最终组合的固定配置；每项能独立关闭。
- WORKLOG.md：指向唯一权威日志report/worklog.md；整理前归档现有详细版本，保留日期与提交关联。
- report/submission/01_technical_report.pdf：≤4页最终技术报告，保留可编辑源稿。
- report/submission/02_ai_usage.md或PDF：1页AI说明。
- artifacts/与manifests/：精简结果、配置、命令、来源和校验清单，证据可访问。

原题未要求把所有tensor、trace、模型、虚拟环境放进Git。保留代码、脚本、结果摘要、逐题评分与覆盖率、失败/超时统计、环境及模型/输入指纹和必要profiling证据；大trace/张量可选择性压缩归档并提供SHA256和可访问位置。仅写本机绝对路径不足以让收件人核验关键结论。现有Step0时期备份不等于已备份全部Step1产物，最终应补统一证据清单与离机保存。

HF参考及评测客户端独立环境须明确列作验证工具；不得让最终ATOM启动脚本依赖升级后的HF环境、其他实验worktree、旧results目录或网络安装。保留引用的开源来源、版本/commit、文件路径和原有许可证。

## 4. 必填消融与结论口径

技术报告至少有如下真实实测表，每行写卡数、实际版本与配置，列A tokens/s/GPU、B TPOT p50、C TPOT p99/TTFT p99：

| 行 | 数据要求 |
| --- | --- |
| Step0（1卡） | 真正Step0配置；为HTTP/批处理接入而做的必要变化单独解释 |
| +点1 | 同一评测协议下的独立增益 |
| +点1+2 | 累加结果，同时保留点2独立关闭说明 |
| +点1+2+3 | 最终组合；若最终少于3点，明确实际点数及不适用行 |

当前后续实验中的R配置已含批处理/shape控制/共享路由等变化，不能不加解释就把R重新标作原始Step0。A64与A512、C20与C200、单次测量与三次中位数必须明确分开。未完成数据写缺失/失败，不补造数值。

正确性以题目指标为准，不要求每个中间张量逐位相同。最终组合仍应验证公开200/16k/HumanEval；开发集与官方隐藏集结论区分。已有149/164对HF145/164为高2.4390pp，原绝对差脚本判False需保留，不能在没有解释或裁判确认时静默改成严格2pp通过；同时如实报告没有观察到功能得分下降，不通过降低模型表现迎合阈值。

## 5. 剩余工作优先级

**立即并行做CPU侧交付整理**：选定提交候选、整理代码与配置关系、准备报告和AI说明实际内容、汇总已有证据；不触碰正在运行的fastpaths工作区。

**实验结果返回后优先收敛**：只整合有收益机制，冻结至多3点及独立开关，建立统一server入口。集成版本先做静态/CPU检查和HTTP冒烟，再补最终组合必要正确性；不重跑全部历史诊断。

**最后完成验收测量与提交**：固定版本跑完整ABC及必填消融，保存错误/超时和参数；资源允许再做重复测量，但不能把裁判的3次隐藏集复测描述为已由我们完成。用干净克隆在给定容器验证单命令启动、文档链接、开关、页数和证据哈希，最后正常合入交付分支、打标签、推送与提交材料。
