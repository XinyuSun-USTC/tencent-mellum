# 场景 C：分段预填充与解码服务保障

## 当前目标与基线

当前最高优先级是解决 C200 超时，不继续扩展无关优化。已验收组合为专家分组 4 + KV 单次写入；其本地正确性通过，但 C200 仅 1/200 成功。保持该工作树不变，本轮在 `tencent-mellum-qualified-chunked` 独立开发。

`Scheduler.schedule()` 原实现先恢复部分预填充、再接受新预填充，有预填充就返回，最后才走解码。仅减小预填充 token 预算不能保证解码服务。参考 `ragged_prefill()` 原本要求 Q/K 边界相同、位置从零起，因而不支持缓存后缀。本轮同时修改这两项限制。

## 实现范围

- 新增 `mellum_chunked.py`：用绝对位置校验 suffix，按原分页块表读取已旋转的 K/V；全局注意力使用偏移因果遮罩，滑窗注意力额外限制 `query-window < key <= query`，仅移除对所有当前 query 均不可见的历史键。
- 保持 Torch SDPA、参考 RoPE、BF16、独立 QKV 与现有专家路径。不替换为原生注意力，不启用前缀命中或 graph。
- Direct KV 在本路径保留当前 chunk 的 Q/K/V，由参考桥接层读取历史，避免再执行旧原生 prefix gather。
- 新增默认关闭的 `MELLUM_C_DECODE_STEPS`：每个预填充分段之后，只要存在已完成预填充的请求，就优先服务最多四轮解码；未完成预填充的请求保留在运行队列中，不作为解码请求执行。没有可解码请求时继续预填充，避免空转。
- 三个候选为 chunk512/1024/2048，解码配额均为四轮。分段上限与模型最大上下文分别设置，模型长度仍为 16640。

CPU 测试覆盖绝对位置、全局及滑窗 mask、滑窗边界、非连续物理块的 NHD/SHUFFLE KV 读取、分段 SDPA 与整段参考对照，以及部分预填充和已就绪解码共同存在时的调度轮转。CPU 测试不能替代 AMD GPU 的运行及数值验证。

## 第一轮 GPU 筛查

`scripts/run_mellum_c_chunk_screen.py` 每个配置先执行四条提示的单独及四请求生成，覆盖短输入、滑窗边界和 16k。记录与已有 HF 前八 token 的匹配情况、分页后缀实际执行记录和完整加载结果；这是小样本筛查，不宣布正式正确性通过。输出不完整或没有实际缓存预填充则停止该配置的容量测试。

随后运行 C60：原始 C 数据前 60 请求、速率 0.3、输出 256、单请求超时 180，保留实际客户端数据库。C60 能比 C20 更充分暴露持续积压，但仍不能替代 C200。若小样本生成有差异，结果保留待分析；不因为生成文本不同就自动否定性能试验，也不能忽略最终题面正确性门槛。

两张卡可独立批量运行：GPU0 测 chunk512、1024；GPU1 在相同源码下测未分段组合对照、chunk2048。每个配置独立进程，失败记录后继续下一个配置。整个分支在实验结束前冻结。预计每条批任务约 20–40 分钟，受小样本长输入和失败排空影响；60 分钟为整项预算，非单请求超时。

选择依据为完成率、请求时延、TTFT/TPOT、批量和预填充分段记录；不只看成功请求 p99。若某个配置有实际改善，再测该配置 C200，并只对最终候选补完整正确性验收。若 C60 仍明显失败，不能盲目重跑全套验收或宣称 chunking 已解决问题。

## 待做选项（本轮不实施）

| 方向 | 用途与后续条件 |
|---|---|
| 参考滑窗 mask 和元数据复用 | 降低预填充辅助开销，等分段调度收益确认后再做 |
| 公共前缀缓存 | 减少 C 重复预填充，须先验证缓存后缀的正确执行 |
| SWA KV 存储/索引截断 | 检查现有逻辑截取之外是否仍有额外空间及管理收益 |
| 超时取消与资源回收 | 已发现前端清理缺口，需单独验证引擎取消，不能假定其是唯一根因 |
| 双卡 Prefill/Decode 分离 | 高集成成本，涉及 KV 传输、资源核算和双卡正确性验收 |
| 原生内核、graph、算子融合 | 保留已有失败证据；需要重新定位差异，当前不混入 |

若处理能力本身仍低于持续负载，调度优化不能无限消除积压。目标是在原题参数下实测完成，不提高超时、不降低请求率，也不缓存生成答案。

## GPU 实验期间的 CPU 汇总准备

交付工作树新增 `scripts/analyze_mellum_c_capacity.py`，只读取已结束且产物哈希匹配的实验，不修改正在运行的分支、不导入模型、不反序列化客户端响应 pickle。支持本轮 C 分段筛查的候选结果结构及此前容量结果。三项测试覆盖超时分母、部分流、批次排序和未完成实验拒绝。

旧 C200 的 199 条失败中，39 条有 HTTP 流间隔，160 条无流间隔；最多连续 12 个预填充批次未穿插解码。C20 对应最大连续数为 6。记录不含批次时间戳，不能据此给出停顿毫秒数或断言全部超时由 prefill 引起。分析归档见 `artifacts/submission/c_capacity_analysis/`。

待两组实验结束后，将它们的实际目录传给 `--runs`，统一比较同为 C60 的控制组与三个分段配置；失败配置仍列为未测量/失败，不静默剔除。若均无改善，优先重新检查主要算时、调度执行记录和取消回收，不直接继续完整 HumanEval。
