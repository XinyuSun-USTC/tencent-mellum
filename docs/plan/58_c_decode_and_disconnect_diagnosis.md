# C 第三阶段：隔离解码能力与断连后的引擎工作

## 为什么停止继续扫调度参数

一轮配额1024/2048的C60仅14/60、2/60；公共前缀缓存真实复用了224672输入token（35.47%），未分段缓存组准入等待中位约0秒，但仍58条已有流式输出后超时。因此不能将失败全部归为等待prefill，也不能继续用更多chunk参数替代计算和生命周期分析。

本阶段分支 `step1/c-service-diagnosis`，工作树 `/workspace/tencent-mellum-c-service-diagnosis`，基于e4b4909。没有改变模型数学、请求超时、prefix规则或验收门槛。仅增加默认关闭的EngineCore阶段审计和两个诊断工具流程。

## GPU0：隔离预填充后的批量解码

固定参考组合 `r_expert_decode4_kv_once`、BF16/eager、32槽、prefix/chunk关闭，使用C数据前32条真实输入。一次性提交1/4/8/16/32请求，各输出128token；提交后不再有新请求。每个批次均完成其预填充，随后统计最后一次prefill结束后的实际回调交付与decode工作。引擎一次加载，先做短预热，不将预热计入。

同时保存：实际请求输出长度、逐token回调、EngineCore阶段起止与请求ID、队列长度、完成ID、实际调度token数。实际交付token与调度token分开：deferred机制可能产生额外forward，不能用调度工作冒充交付吞吐。最后一批回执必须确认写入，不能假设收到输出时最后审计已落盘。

单卡C要求的输出需求为0.3×256=76.8token/s。若这组无新增prefill的实测交付速率已经明显低于需求，应优先降低批量decode执行代价；它不是整个数据集的理论上界。若明显高于需求，则进一步研究混合阶段、准入与取消开销。离线128token结果也不直接替代HTTP C256成绩。

## GPU1：真实HTTP断连后的工作观测

每个用例独立启动并终止同一参考组合服务，只提交一个真实C输入：

1. 正常生成8token并读到DONE，作为完成正对照。
2. 请求256token，收到初始role帧即主动关闭连接。
3. 请求256token，收到首个实际content/reasoning帧后关闭连接。

每次关闭后观察15秒，按单调时钟关联该seq_id的EngineCore回执：区分关闭前已开始的inflight工作，及关闭后新开始的步骤，记录是否自然完成。没有后续记录只表示观察窗口内未看到，不能自动证明资源已回收；存在新步骤则可证明该请求仍参与计算，但其主机耗时不等于GPU浪费时间。

源码已知清理函数在生成器正常末尾，提前退出缺少finally保证；api_server清理只删前端映射，EngineCore未处理ABORT。这些是已读源码事实，但其对C200的影响未量化。此轮不先写KV释放修复，避免在尚有异步forward时释放正被GPU使用的块。

## 计时与清理边界

`--phase-audit`显式设置`MELLUM_ENGINE_PHASE_AUDIT`，默认关闭。新增`mellum_service_audit.record_step()`记录主机schedule/forward等待/postprocess时间，无CUDA同步或硬件计数器，不称GPU kernel计时。JSONL记录本身有扰动，所得数据用于定位，不作为最终性能分数。

所有任务由`run_stage`管理独立进程组。断连服务继承其用例worker组，正常/异常/超时均清理该组内后代，不终止其他卡或用户进程。每个HTTP用例单独加载模型，遗留请求不污染下一用例。解码任务有总预算、断连用例各有上限；没有提高题面180秒超时来报告通过。

## 测试与后续选择

155项CPU检查通过，包括已有调度/块管理/前缀/缓存几何回归、审计默认关闭、实际交付计数、最后prefill后的阶段筛选，以及断连时inflight与新步骤区分。GPU尚待执行。

| 观察 | 下一步 |
|---|---|
| 隔离decode也明显不足 | 依据批大小曲线，优先研究按请求attention/KV gather或投影调用粒度；先做单变量小组验证，不整条替换原生路径 |
| 隔离decode有充分余量，混合负载仍失败 | 用同一阶段审计进一步检查prefill插入、调度预算和实际输入复用，不把单次profile间隙都归CPU |
| 断连后仍持续新调度 | 单独修复生成器finally及主线程abort队列，协调异步forward完成后再释放KV；再对照验证，不预先承诺解决全部容量 |
| 两项均有问题 | 分开实现并测增量，保留旧对照，最终组合只集中做完整验收 |

本轮预计解码组约10–25分钟，断连组约3–8分钟，受模型加载和设备状态影响；40/20分钟为总预算。两卡为独立实验，共享主机资源须披露。不重跑HumanEval、完整ABC或当前已失败候选C200。
